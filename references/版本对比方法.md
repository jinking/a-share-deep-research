# 版本对比方法（同一标的多版研报对照）

## 适用场景

同一只股票先后产出过多版研报（如「快速版」→「SOP 完整版」），用户要求对比两版差异。
**原版一律原样保留，不覆盖、不删除**——对比的价值恰恰在于保留各自的原始形态。

## 命名约定

| 版本 | 文件名 |
|---|---|
| 旧版（原样保留） | `<名称><代码>_深度研究_<YYYYMMDD_HHMMSS>.html`（历史产物可只到日期，新产物一律到秒） |
| 新版（SOP 版） | `<名称><代码>_深度研究_SOP版_<YYYYMMDD_HHMMSS>.html` |
| 对比页 | `<名称><代码>_两版研报对比_<YYYYMMDD_HHMMSS>.html` |

三个版本落盘后各跑一次 `scripts/stamp_report.py <报告> --rename`，时间戳与文件名一次对齐。

## 对比页固定结构（7 章）

1. **一句话对比结论** —— 结论方向是否变化？若没变，说清「变的是证据质量还是结论本身」。
2. **两版基本信息对照** —— 出品时间、方法路由、取数方式、体量（章节数/字数）、是否交叉验证。
3. **核心结论对照** —— 逐条并排：V1 结论 / V2 结论 / 判定（同向·加强·修正·推翻）。
4. **方法论覆盖度对比** —— 对照 16 章 SOP，逐章标 V1 有无、V2 有无。
5. **数据核对** —— 三分法：
   - 5.1 两版完全一致的硬数据（证明基础数据都可靠，增强可信度）
   - 5.2 V2 修正的数据错误（列明 V1 错值、V2 正确值、错因）
   - 5.3 V2 新增的关键事实（V1 完全没有的信息）
6. **结论稳定性评估** —— 用「两版同向 = 结论稳健」或「两版分歧 = 需进一步验证」收口，并指出分歧根源。
7. **两版的写作定位差异** —— 各自适合什么读者/什么用途（如 V1 快读、V2 决策）。

## 硬规则

- 对比必须**基于两版实际文本**逐条核对，不得凭记忆或印象编写。
- 凡 V1 有错、V2 修正的，**必须写明错因**（如摘要口径错配、媒体非一手来源、单位误用），
  不能只写「V2 更准」。
- 数据核对章的「一致项」不可省略——它是判断数据基线可靠性的依据。
- 对比页同样执行交付前内联 JS 语法自检（若含图表脚本）。
